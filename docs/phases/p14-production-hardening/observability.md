# Observability: metrics, SLOs, alerts, dashboards, tracing

Status: **implemented and unit/promtool-tested; not yet run against a deployed multi-host stack.**
Everything here builds on the existing `Metrics` registry (`crawler2/core/observability/metrics.py`)
and structured logs; there is no second monitoring system.

## 1. Metrics endpoints

Every long-running crawler2 process exposes Prometheus text on `/metrics`. One process per port; the
port is `metrics.port` (default **9100**) plus a fixed per-role offset
(`ROLE_PORT_OFFSETS`, `crawler2/core/observability/metrics.py`):

| Role (command) | Port | | Role (command) | Port |
|---|---|---|---|---|
| `crawler2-worker --pool http` | 9101 | | `crawler2-media resolve run` | 9107 |
| `crawler2-worker --pool browser` | 9102 | | `crawler2-media probe run` | 9108 |
| `crawler2-worker --pool tor` | 9103 | | `crawler2-media hash run` | 9109 |
| `crawler2-extract` | 9104 | | `crawler2-media representations run` | 9110 |
| `crawler2-storage relay` | 9105 | | `crawler2-intel sources run` | 9111 |
| `crawler2-discover admit` | 9106 | | `crawler2-intel feedback run` | 9112 |
| `crawler2-evidence collect run` | 9113 | | `crawler2-exporter` | 9114 |

Worker pools with `processes > 1` start child processes that share a pool port: only the first binds;
the others log `metrics_bind_failed` and carry on (a lost port must not become lost work).
Collisions with `node_exporter` (9100) cannot happen: no role uses the base port.

* **Bind address.** `metrics.bind` defaults to `127.0.0.1`. On a host scraped by a remote Prometheus set
  `CRAWLER2_METRICS__BIND` to the *private* interface address and restrict the port in the host firewall.
  Metrics are unauthenticated and name pools/outcomes only (labels are bounded; never URLs, hosts or ids).
* **What no worker can say about itself** (queue depth, consumer lag, oldest unacknowledged event,
  outbox backlog, Redis memory, dead letters, GPU) is exported by **`crawler2-exporter`** (port 9114,
  one per deployment, plus `--gpu` on the GPU host). It reads on scrape, caches for `--min-interval`
  (15 s), and reports `crawler2_exporter_source_up{source}`; an unreadable source's series are *absent*,
  never zero.
* **Not yet covered (gaps).** FP-1: the fingerprinter starts `/metrics` only when `metrics_port` is set
  (`fp:fingerprinter/cli.py:180`) and its encode-latency/match-latency histograms were not verified;
  the SLIs that need them are marked *gap* below. X-1: the evidence finalizer has a counter but no latency
  histogram. Redis/Scylla/MinIO/host use their standard exporters (`redis_exporter`, Scylla `:9180`,
  MinIO v2 metrics, `node_exporter`) named in `deploy/observability/prometheus/prometheus.yml`.

## 3. SLIs and SLOs

All targets below are **proposals pending owner approval** (OD-P14-3). Units, windows and sources are
fixed; numbers are what the alert rules use today, so approving or changing them is a one-line edit.

| SLI | Definition (unit) | Window | Proposed objective | Source / PromQL | Alert |
|---|---|---|---|---|---|
| Fetch success (non-blocked) | attempts ending `ok`/`not_modified`/`media` ÷ attempts excluding `blocked`,`captcha`,`http_error`,`cancelled`,`fetcher_unavailable` (ratio) | 1 h | ≥ 0.90 *(P4 methodology still open, TC-007)* | `sum(rate(crawler2_fetch_attempts_total{outcome=~"ok\|not_modified\|media"}[1h])) / sum(rate(crawler2_fetch_attempts_total{outcome!~"blocked\|captcha\|http_error\|cancelled\|fetcher_unavailable"}[1h]))` | `FetchFailureRatioHigh` (transport failures > 0.5, 15 m) |
| Frontier progress | any fetch attempt completed while tasks wait (bool) | 30 m | never idle with depth > 1000 | `sum(crawler2_frontier_depth)`, `rate(crawler2_fetch_attempts_total[30m])` | `FrontierNotDraining` |
| Queue age | oldest unacknowledged event per consumer group (s) | max over 10 m | ≤ 600 s | `crawler2_stream_group_oldest_pending_age_seconds` | `ConsumerStalled` |
| Event lag | undelivered entries per group (count), must not trend up | 30 m | no sustained growth above 5,000 | `crawler2_stream_group_lag` | `EventLagGrowing` |
| Outbox backlog | worst relay checkpoint age (s), includes the settle window | 10 m | ≤ 900 s | `crawler2_outbox_checkpoint_lag_seconds` | `OutboxRelayBehind`, `OutboxLateRows`, `OutboxPublishFailures` |
| Dead letters | growth of the dead-letter set (count/h) | 1 h | 0 | `increase(crawler2_frontier_dead_letters[1h])` | `DeadLettersGrowing` |
| Retries / storage errors | `fetch_record_errors`, `object_store_errors` increases (count) | 15 m | 0 sustained | counters | `FetchRecordErrors`, `ObjectStoreErrors` |
| Worker restarts | `changes(process_start_time_seconds[1h])` | 1 h | ≤ 3 | prometheus_client built-in | `ProcessRestarting` |
| Storage latency | p99 of `object_store_seconds`; Scylla p99 from its exporter (s) | 5 m | P2 targets (RF=3 pending, TC-013) | histogram | — (no alert until targets exist) |
| Redis memory | used ÷ maxmemory (ratio) | 10 m | < 0.8 | `redis_memory_used_bytes / redis_memory_max_bytes` | `RedisMemoryHigh/Critical`, `RedisEvictions` |
| Disk | free ÷ size per mount; 24 h projection | 10 m | ≥ 0.10 and not filling within 24 h | node_exporter | `DiskSpaceLow`, `DiskWillFillIn24h` |
| GPU memory | used ÷ total (ratio) | 10 m | < 0.95 | `crawler2_gpu_*` (exporter `--gpu`) | `GpuMemoryHigh` |
| Encode latency per minute of media | *gap* (FP-1) | — | owner/P9 to define | needs fp histogram | none |
| Match latency | *gap* (FP-1) | — | owner/P10 to define | needs fp histogram | none |
| Evidence finalize latency | *gap* (X-1) | — | owner to define | needs a latency histogram in `evidence/finalize.py` | none |

An alert that depends on a metric nothing produces is a defect: `tests/unit/test_observability_config.py`
fails the build for one. `ScyllaPendingCompactions` uses a Scylla metric name that was **not verified**
against a running cluster (its rule says so); treat it as inert until checked.

## 4. Correlating one task from crawl to evidence

The envelope already has `correlation_id` ("shared by every event in one causal chain"), `causation_id`
and a `metadata` map for trace ids (`antipiracy_contracts/events/envelope.py`), so **no contract change
was needed** (B.5 #5 preserved).

What propagates today (verified by code reading and `tests/unit/crawlers/test_recorder_trace.py`):

| Hop | correlation_id |
|---|---|
| `fetch.completed`, `page.observed` | **new per recorded attempt** (added in P14 — before it, the chain had no root) |
| `page.changed`, `urls.discovered`, `media.discovered` (extraction) | inherited from the `page.observed` cause, `causation_id` = that event |
| `media.observed`, `encode.requested` (media registry) | inherited from `media.discovered` |
| `representation.ready`, `encode.failed`, `match.found` (fingerprinter) | **not propagated** (gap TR-1; fingerprinter repo) |
| `evidence.finalized` | **not propagated**; candidate creation emits no event (gap TR-2; needs the correlation stored with the candidate, V008) |

Past the registry the chain continues by shared ids (content id → representation id → match id → evidence
id). `crawler2-trace NEEDLE` (`crawler2/diagnostics/trace.py`) searches the retained streams for any id,
widens to the correlation ids it finds, and prints the chain in time order. Streams are trimmed
(ADR-022): for old work use the durable copies (`crawler2-media show`, `crawler2-evidence show`).
A full crawl → evidence trace on real data does not exist yet because no real `match.found` does
(P10 calibration held); this is **not demonstrated**, only the mechanism and its unit tests.
